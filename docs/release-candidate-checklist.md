# Release Candidate Checklist

Use this checklist before publishing a v1 release candidate. A release candidate is not final v1.0 until every required check is complete and reviewed.

## Required Automated Gates

- `npm ci` completed from the committed `package-lock.json`.
- `npm run release:rc-check` completed successfully.
- CI completed successfully on the release-candidate branch or tag candidate.
- `release/` was generated by CI or from a clean checkout.
- `release/SHA256SUMS` verifies with `npm run release:check` and `sha256sum -c SHA256SUMS`.
- `release/release-manifest.json` version matches `package.json`.
- Lockfile hash in `release/release-manifest.json` matches the reviewed `package-lock.json`.

## Required Review Gates

- Dependency tree and lockfile changes reviewed.
- `npm audit --audit-level=moderate` output reviewed.
- `docs/accessibility-checklist.md` completed against a production build.
- Real-device visual QA completed for Home, Marketplace, listing pages, Create Listing, Trade, Reputation, Profile, Mediators, and Settings.
- Security promises spot check completed:
  - Saving does not publish.
  - Relay fetch does not import automatically.
  - Synced public records stay separate from local user-owned records.
  - Agreement terms, full dispute details, evidence metadata, local filenames, private keys, encrypted identity blobs, payment secrets, and settlement text do not enter public serializers.

## Release Artifact Handling

- Create a signed annotated tag only after automated and manual gates pass:

```bash
git tag -s v0.40.0-rc.1 -m "AgoraMesh v0.40.0 RC 1"
git push origin v0.40.0-rc.1
```

- Attach verified artifacts manually if creating a GitHub Release.
- Publish `SHA256SUMS`, `release-manifest.json`, and release notes with the artifact.
- Do not publish artifacts from a dirty checkout, unreviewed dependency tree, or failed checksum verification.

## Deferred Post-RC Work

- Private Nostr trade coordination protocol design.
- WebLN wallet execution, NWC background polling, and automated payment confirmation.
- Deeper spam/moderation triage.
- Relay score tuning from real-world usage.
- Conflict merge and explicit version-selection UX.
